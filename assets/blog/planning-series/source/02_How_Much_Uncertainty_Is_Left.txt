How Much Uncertainty Is Left?
Estimate the unknowns inside a stated decision model
Jonathan Nacionales
Founder, Hermod Labs
November 18, 2026
How much would we learn by obtaining one more record, running a check, or waiting for an observation?
To answer numerically, we first need to specify what remains unknown and when the information could
affect a decision.
Consider a fictional supplier preparing a retail launch. Maya coordinates its shipment recommendation.
Finance permits no more than $5,000, launch wants an early arrival, and operations needs current records
supporting the chosen movement. In the worked shipment story, Direct costs $4,000 and Consolidated
costs $5,000; a current loading confirmation changes which option can be supported.[4]
The calculation below is a new teaching extension. Its probabilities and observation accuracy are stipulated
assumptions, not measured shipment data or outputs from the published application. We use the following
statement to keep choices, evidence, findings, and human decisions separate:
This plan includes plan_contents.
We have checked it under these conditions: assessed_conditions.
The result establishes established_finding.
We favor preferred_options because preference_basis.
Acceptance of next_action is acceptance_status, with decision_owner responsible.
If we observe reassessment_trigger, we will contingency_response before response_deadline.
What exactly is unknown?
An uncertainty estimate needs a fixed question, operating interval, evidence basis, and set of possible
conditions. Let E= e denote the information already available. We describe the uncertain shipment
situation by S = (O, L, T ):
Variable Named field Values in the teaching model
O order_change 0: no additional order revision before a specified release review; 1:
an additional revision.
L loading_window_status 0: loading window usable at the planned loading time; 1: lost.
T transit_duration 0: quoted duration; 1: one day longer.
These are conditions of the operation. Selecting a carrier is a decision about what to do; it is not an
observation of O, L, or T . A loading slot means a reserved time window. The named information fields
identify the quantities whose values or distributions we need to represent.
The chosen scenario set is Ω = {0, 1}3. It admits eight combinations. That is a modeling choice:
other delays, interruptions, and order changes outside the stated interval are not silently included. The
assessed_conditions must retain that boundary as well as the supporting records.

The other slots in the decision statement also have different jobs. plan_contents records a selected
arrangement. established_finding records an assessment claim. acceptance_status records a human
decision. Unknown values in any of these can be studied, but the same probability model does not
automatically apply to all of them. Settling a choice is different from learning a fact about the world.

How much can an observation teach us?
Return to the equal-probability, independent model with three bits of initial uncertainty. A perfect
observation of O leaves four equally likely combinations of L and T , so the residual entropy is two bits.
Observing both O and L perfectly leaves one bit about T.
“Perfect observation” is an ideal information assumption, not a claim that future events can be known
in advance. For O, it could mean observing the authoritative order state at the specified release review
before a later commitment. Transit information obtained only after arrival cannot inform an earlier
booking decision. The time of each decision and observation must be part of the model.

What if the check can be wrong?
Suppose Y reports O correctly with probability 0.9 in either state, with a symmetrical error probability
of 0.1. Its errors are independent of L, T given O, and the fair prior still applies. Bayes’ rule gives
p(O= y |Y= y, e) = 0.9, H(O |Y= y, e) = h2(0.1) = 0.4690. (8)

What should an actual estimate retain?
An estimate should identify the variable meanings and time points, possible values, available evidence,
probability sources, dependencies, and excluded conditions. Observation models need their accuracy and
availability time. A statement such as “three bits remain” should travel with that information.
If data do not justify probabilities, retain the possible scenarios, constraints, and support for their
inclusion. Report what has been examined and where a plan is vulnerable. A count of successful
unweighted scenarios is not automatically a success probability. Robust decision making supplies methods
for examining strategies across plausible futures without requiring one trusted forecast. [3]
The report should also distinguish uncertainty about the full state from uncertainty relevant to the
required answer. Several possible states may all support the same next action. Learning which of those
states holds could remove entropy without improving the decision. Information has decision value through
the choices it enables.[2]
Put the calculation beside the decision record
For this teaching case, assessed_conditions would retain the three variables, their time points, the
eight-state scope, and the stipulated prior. The established_finding could report the calculated expected
gain of 0.5310 bits for the specified noisy observation. It should not report that an operating plan or an
approval has thereby been established.
Decision Lab’s linked shipment example evaluates arrangements and preserves their supporting report.
The calculations here are a separate illustrative probability layer, not a claim that the current application
produces calibrated entropy estimates. A practical extension would need reviewed variable meanings,
probabilities, observation models, and an explicit connection to the operating decision.
Before obtaining an observation, finish this sentence: “We expect to learn about assessed_conditions
from this check, by this time, with this reliability. If its result differs, which action could change?” The
last question leads from information gain to the value of the plan.
