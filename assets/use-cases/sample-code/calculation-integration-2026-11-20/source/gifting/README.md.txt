# Gifting integrations

These examples form one continuing team process:

- [Gift-kit Preflight](gift-kit-preflight/README.md) uses the public CLI to screen independent campaigns and export a portable native review with owners, source receipts and the next action.
- [Python gift-kit workflow](gift-kit-review/README.md) uses the Python SDK to retain conservative screening, review scoped evidence and calculate planning through separate explicit review actions. Its bundled-runtime wheel needs no system Node/npm.
- [Gift-kit Handoff Desk](gift-kit-handoff-desk/README.md) uses the public SDK and ordinary React hooks to resolve one of those exact reviews, record an operating decision and retain actual correction/rehearsal/handoff records.

The current JavaScript clients use calculation-mode workflow 4.0.0 around the
unchanged cost-first version 3 operating apps. The tradeoff stays concrete: cheap in-house correction when time permits, a premium external package when it alone protects the cutoff, and less work only when actual scoped diagnostic evidence supports it. Existing version 2 marketplace releases remain immutable.

The apps share native workflow history and source/assessment identity checks; the Node and React clients also share operating-record integration code. Domain rules come from portable configuration, and reports use the reusable views. No client performs production, authenticates external approvals or guarantees a shared resource across campaigns.

Apply current facts, then Calculate/Recalculate. The SDK supplies the focused
Decision summary and compact comparison; exact-option Supporting reports,
Decision process and Calculation dependencies remain available for inspection.
An inspection does not select a package. A current complete feasible assessment
supports a separate operating choice, with sourced authorization and actual
correction, fresh rehearsal and handoff still recorded separately. A later failed
rehearsal supersedes a previous positive record.

The prior reviewed v3 definition and historical runs retain their original
contract. They can be inspected/exported or used as the input basis for a new
analysis, without copying prior operating authority or pretending acceptance
steps disappeared. The Python example still intentionally uses that reviewed v3
definition.

Reproduce the new workflow release with
`node scripts/build-integration-calculation-journeys.mjs`, then synchronize
standalone fixtures with `node examples/gifting/clients/generate.mjs`. Both
commands support `--check`. The frozen app packages, model assumptions and
original cases remain unchanged. See [shared integration contracts](../shared/README.md).
