01 / Keep the relationships visible

What still holds
after a change?

A review connects an arrangement to the requirements it is intended to satisfy, the observations that support a claim, and the people responsible for follow-up work.

When the arrangement changes, those connections give reviewers a starting point: which claims depend on what changed, which observations still apply, and which decisions need to be revisited?

Change Review Lab applies Hermod’s strategy engineering platform to that task. Security is our current commercialization focus within the broader platform.

02 / An illustrative modeled change

One new access path.
Several reasons to review.

Suppose a team adds a remote administration path to a system. This example shows the reasoning a change review can make explicit.

01

Describe the original arrangement.

The model connects approved administrators, an existing access path, and the observations used to support a claim about restricted access.

The claim has a scope and supporting conditions.

02

Introduce the change.

A new access path changes the arrangement. Evidence about the original path may leave the new path unexamined.

A previous observation may need a fresh check.

03

Revisit affected claims.

A reviewer examines who can use the new path, which conditions govern access, and what observations are needed to support the revised arrangement.

Record the questions, owners, and follow-up work.

The useful result: an explicit connection between the change, the claims it affects, and the work a reviewer needs to reconsider.

This is an illustrative review scenario. What the tool can identify depends on the relationships represented in the model and the evidence available to the reviewer.
