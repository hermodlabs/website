01 / What you do in the beta

Write. Analyze.
Inspect and revise.

Start with a small question: can a report be prepared and reviewed by day three? Explore the model and its result below, then use the walkthrough to run and change it yourself.

01

Write the description.

Open a blank description or an existing file in Workspaces, then select Author → Description. Enter named work, resources, requirements, and explicit connections using the supported phrases. You decide which facts and rules belong in the model.

Manual entry · visible source

02

Analyze and inspect.

Select Analyze to evaluate the supplied description. Inspect returned arrangements, their required checks, and the timing report. A schedule can fit while a required check remains pending.

Calculated fit · unresolved checks

03

Revise and keep a copy.

Clarify assumptions with the people involved, edit the description, and analyze again. Use Export to keep a complete description you can reopen, alongside the analysis results or readable planning report.

Human judgment · portable files

01 / Read the meaning behind the code

The statements describe two ontologies.

An ontology names the kinds of things in a problem and how they relate. Phrase patterns map the code’s statements to the work, people, and calendar shown here.

Work and requirements

What needs to happen.

Phrase pattern

"<objective>" requires all of "<step>", "<step>".

"Reviewed report" requires all of "Prepare report", "Independent review".

02 / Join the maps

Two patterns connect the ontologies.

Each statement refers back to a step already declared. It connects that step to a resource or shift from the other ontology.
